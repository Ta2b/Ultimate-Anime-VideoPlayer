Version 0.7.0-rc.4, **quatrième préversion candidate à la 1.0** : RTX HDR sous Windows enfin chargé par le bon chemin. Linux x86-64 (AppImage et archive), Windows x64 (installeur et archive) et macOS (dmg et zip). La 1.0 sera déclarée par Tatoub seul.

## RTX HDR sous Windows
- **Le lecteur charge maintenant le pont `aji_rtx.dll`** (fonctions `aji_rtx_create`, `aji_rtx_eval` et `aji_rtx_shutdown`), qui lie NGX et charge `nvngx_truehdr.dll` à côté de lui. Avant, il cherchait une `rtx_video_api.dll` qui n'existe pas dans le SDK : RTX HDR ne pouvait pas démarrer sous Windows.
- **Dossier à importer** : il doit contenir `aji_rtx.dll`, `nvngx_truehdr.dll`, `nvngx_vsr.dll` et `cudart64_12.dll`. Si `aji_rtx.dll` ou `nvngx_truehdr.dll` manque, le lecteur le dit avec le nom du fichier.
- La version du SDK se lit sur `nvngx_truehdr.dll` (le pont n'a pas de numéro de version).

## Autres
- Aucun changement pour Linux et macOS. L'empreinte TensorRT change (le code du pont est dans le moteur) : le paquet TensorRT Linux est refait pour cette version.

## Limites connues
Celles de la rc.1, de la rc.2 et de la rc.3. **Ce chargeur n'a pas été exécuté sur Windows** : signatures relevées dans la source du pont, tests unitaires avec un faux pont seulement. Ton essai de RTX HDR sous Windows (SDK importé, image HDR obtenue) est la première vérification réelle.
